## 复现检查

在仓库根目录执行：

```sh
python3 mlir/insider-compiler/issues/evidence/ch13/verify_front.py
```

脚本直接读取正式 Markdown，将同一清单的跨页代码围栏拼接到 `front-listings/`，保存[检查结果](front-check-results.json)。本次使用 Python 3.14.3，实际完成：

- 清单 13-1、13-2：`ast.parse` 与 `compile()` 语法检查通过。未导入 Triton、未调用装饰器、未执行内核。
- 其余 33 份 MLIR 清单：词法层面的括号、尖括号平衡检查通过；清单 13-11 为抽象布局映射，单独提取。
- 23 份完整函数示例：全部 SSA 名称均能找到文字定义。清单 13-12～13-19、13-23、13-24 是操作片段，保留对所在上下文输入的依赖，不套用完整函数的名称覆盖检查。
- 表 13-3：由 `sizePerThread=[2,2]`、`threadsPerWarp=[8,4]`、`warpsPerCTA=[1,2]`、`order=[1,0]` 计算全部 256 个元素的线程归属；96 个显式表格单元通过对照，64 个线程各有 4 个元素。
- 表 13-6：计算全部 256 个元素的共享内存 swizzle，16 行均为双射且自逆；55 个显式表格单元通过对照。原公式漏掉组内偏移，每行只能得到 8 个不同列号，正确公式产生 16 个。

这些检查用于发现转写破损与公式错误，**不是 Triton parser/verifier、SSA 支配关系证明、Pass 执行或数值正确性测试**。本机没有配套 `triton-opt`，未执行 PTX/CUBIN 生成或 GPU 性能测试。清单中的省略依赖、结构测试输入、地址有效性限制与原书/源码差异在正文及校订记录中分别说明。
