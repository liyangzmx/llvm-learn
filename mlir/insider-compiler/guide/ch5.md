# 第5章读前导读：把变换安排到正确的操作上

[原章](../insider-compiler-ch5.md) · [配套精华笔记](../notes/ch5.md) · [导读目录](README.md)

## 本章要解决的问题

有了合法操作和可查询的接口，接下来要决定：哪个变换处理哪层 IR，按什么顺序运行，失败时怎样定位，已有分析还能不能继续使用。第5章把这些责任放进 Pass 系统。阅读时不要把它只当成一份“怎样注册命令行选项”的教程，真正重要的是调度范围与状态管理。

## 先把两个模型放在一起

第一，IR 有层级：模块可包含函数，函数再包含其他操作。第二，流水线也有层级：每个管理器选定锚点，在该操作上按序执行 Pass，必要时把子流水线交给嵌套操作。两种层级要对应，但普通 Pass 内部仍可自行遍历获准处理的 IR，不能据此认为全书只遍历一次。

另一个需要复习的概念是缓存。分析读取 IR 并计算信息；缓存能减少重复计算，但 IR 改变后结果可能过时。记住这一矛盾，再读5.2的查询与保留接口，会比单独背函数名容易。

## 按原章安排阅读

**5.1.1～5.1.3：分开定义、注册、执行。** TD负责描述 Pass、依赖、选项等信息，开发者实现 `runOnOperation()`。注册名字是为了命令行或文本流水线查找；直接通过C++工厂函数加入 Pass 是另一条入口。留意方言注册、加载与 Pass 注册的管理位置不同。

**5.1.4：先画锚点，再读顺序。** 对照 SPIR-V 例子，标明顶层 module、SPIR-V module、SPIR-V函数，以及 `nestAny()` 创建的位置。它是所在管理器的一层子流水线，不会自动递归匹配所有后代。

**5.1.5：把约束理解成并行执行契约。** 问清当前 Pass 能检查谁、修改谁，为什么不能依赖上一次调用留下的状态。需要同时修改多个函数时，应先考虑更合适的上层锚点，而非绕开边界。

**5.1.6～5.1.7：先理解事件，再选工具。** 区分成功与失败回调、分析计算与缓存读取，再看计时、IR打印和复现文件各自观察什么。模块范围打印和局部复现的线程条件值得专门标记。

**5.2：用“何时会过期”串起分析接口。** 不仅关注如何取得分析，还要关注谁负责判断它是否仍有效。保留分析是一项正确性声明，不是要求框架自动修复旧结果。

## 带着这些问题读

1. 通用流水线中的一个 Pass 不适用于某种操作时，会只跳过该 Pass，还是影响整条流水线的适用性？
2. 函数 Pass 为什么不能随意查看另一个函数正在变化的 IR？
3. 同一 Pass 内两次请求分析是否重新计算？在两次请求之间改了 IR 呢？
4. 看到一份复现文件，能否仅凭文件名断定它一定会在本地失败？

本章按本地 LLVM18.1.8 的调度和失效规则阅读。第4章提供了调度过滤和分析所需的接口；第6章会进入 Pass 内部，解释模式怎样匹配、重写以及协调类型转换。
