# 第 10 章精华笔记：公共方言的接口边界

[校订正文](../insider-compiler-ch10.md) · [读前导读](../guide/ch10.md) · [笔记目录](README.md)

## 1. 控制结构与值传递（10.1）

| 方言 | 职责 | 值与控制如何连接 |
| --- | --- | --- |
| func | 函数定义、声明、调用、返回 | 直接调用经符号解析；间接调用使用函数类型的 SSA 值，二者都验证类型 |
| scf | 循环、条件及并行迭代结构 | 区域参数、结果和专门终止操作表达控制与值传递 |
| cf | 基本块级分支、switch、assert | 分支传值给同一 Region 中的目标块参数，不能直接跨区域跳转 |

`FunctionType` 属于 builtin，`func.func` 属于 func。outlining 把一段计算提取为函数，LICM 把不变量移出循环，二者不是同一种“外提”。

`scf.for` 上界不包含、步长为正；循环携带值从初值进入块参数，经 yield 传到下一轮并形成最终结果。`scf.while` 的 before 区域用 `scf.condition` 给出 `i1` 条件及传递值：为真进入 after，为假产生结果；after 的 yield 回到 before。`condition` 并不替代布尔类型。

`scf.forall` 表达多维并行迭代及共享输出合并，`scf.parallel` 可用 reduce 组合结果；二者不直接等于已启动 GPU 线程。`scf.execute_region` 可含多个基本块，所以使用 scf 不表示整份 IR 没有内部 cf 控制流。

## 2. 循环范围折叠的正确规则（10.1.2）

令原循环为 $i=L,L+S,\ldots<U$，若 $k$ 为正整数常量，运算不溢出，且归纳变量相关使用均能保持语义地改写，那么把 $j=ki$ 吸收到循环中需同时更新：

$$
L'=kL,\qquad U'=kU,\qquad S'=kS.
$$

例如 `i = 1 to 4 step 1` 在 `2*i` 处写入，应变成 `j = 2 to 8 step 2` 在 j 处写入，访问集合均为 `{2,4,6}`。本地 LLVM 18.1.8 的 range-folding Pass 遗漏乘法下界更新，不能据它的错误输出学习规则，也不能直接用于此例。

peeling 则调整主循环范围并保留尾部，使主范围长度 `upperBound-lowerBound` 能被步长整除。融合除了边界，还要检查依赖；Transform 中某些接口将独立性或所选分支必执行的前提交给使用者，并不自动证明任意输入合法。

## 3. “转到 LLVM”要处理多条边界（10.1.3）

SCFToCF 展开控制结构，CFToLLVM 处理分支操作，但带 index 的块参数可能要等父函数类型转换后才能继续。算术、函数签名、memref 等表示也有各自的转换责任。

`builtin.unrealized_conversion_cast` 暂接不同阶段的类型，没有运行时数据转换实现。`reconcile-unrealized-casts` 只调和可消除的链；若缺少函数或操作的类型降级，它不能代为完成。转换为 LLVM 方言与随后翻译成 LLVM IR 仍是两个步骤。

## 4. 公共数据方言速查（10.2）

| 小节 | 方言 | 要保留的语义 |
| --- | --- | --- |
| 10.2.1 | builtin | 公共类型、属性及容器；类型被复用不代表永不降级 |
| 10.2.2 | arith | 基础逐元素算术、位运算、比较与转换；不是矩阵乘法或张量归约 |
| 10.2.3 | index | 标量索引运算；最终位宽由转换选项或目标数据布局决定 |
| 10.2.4 | complex | 复数计算；降级可拆成实部、虚部及基础算术或库调用 |
| 10.2.5 | tensor | 不可变张量值、形状与子集操作；更新产生新值 |
| 10.2.6 | sparse_tensor | 稀疏编码、存储和运算支持，配合 sparsification 生成遍历 |
| 10.2.7 | memref | 可变存储引用、布局元数据、访存及生命周期 |
| 10.2.8 | shape | 形状计算、兼容性约束及证据，不只推导静态常量 |
| 10.2.9 | math | 数学函数与相应数值约定，后续选择内建操作或库实现 |

arith 常用 signless 整数，符号解释由具体比较、除法、扩展等操作决定；index 也不等于无符号整数。缩窄位宽及有符号转无符号，需要值域等信息证明结果等价。index 的折叠还要考虑不同目标位宽，不能一律当固定 i64。

ComplexType 的两个分量同类型，源于其只有一个元素类型参数；LLVM 结构体本身允许异构字段。直接降 LLVM 与先分解到 arith/math 的差别在表示与覆盖范围，不是两套数学语义。

## 5. 张量与内存的易混点（10.2.5～10.2.7）

| 操作或表示 | 准确理解 |
| --- | --- |
| `tensor.empty` | 形状给定，内容未指定；不是全零张量 |
| `tensor.cast` | 调整静态形状信息，不重新排列元素；reshape 才改变维度组织 |
| `tensor.extract` / `insert` | 前者得到标量，后者得到更新后的新张量值 |
| `memref.subview` | 从当前视图按偏移、尺寸、步长组合出别名子视图 |
| `memref.reinterpret_cast` | 保留底层指针，用新 offset、sizes、strides 构造描述符；偏移不是直接叠加源视图偏移 |
| `memref.transpose` | 改变形状和步长形成视图，本身不搬移全部元素 |
| `memref.alloc` / `alloca` | 显式分配与自动分配作用域中的局部分配，释放规则不同 |

ranked memref 的典型 LLVM 描述符包含 allocated pointer、aligned pointer、offset、sizes、strides。前者记录原分配，后者用于寻址；memref 不能简单等同于一个裸指针。unranked memref 可以在 MLIR 中使用，只是许多变换要求已知秩。

不要任意 dealloc 别名视图；`assume_alignment` 是调用方提供的对齐承诺，错误时行为未定义，不是运行时检测。形状 reification 接口由生产者操作实现，将 dim 查询转成输入相关计算，也不保证结果一定是常量。

## 6. 约束与数值精度不能在降级时丢失（10.2.8～10.2.9）

`shape.witness` 表示约束证据及相关执行依赖，`shape.assuming` 要求约束已成立，不是条件为假就跳过的 if。本地 `remove-shape-constraints` 将相应广播、相等约束换成真 witness；它假定调用方已保证条件，并不证明这些条件。

普通乘法再加法与一次舍入的 FMA 不总逐位等价；本地 `math-uplift-to-fma` 要求两个操作允许 `contract`。类似地，数学恒等式 `log1p(x)=log(1+x)` 不保证浮点计算精度相同：采用 f32、舍入到最近偶数时，`x=1e-8` 使 `1+x` 舍入为 1，展开结果为 0。

本地 MathToLLVM 默认开启 `approximate-log1p`。需要避免该近似时，应关闭选项并安排满足精度要求的其他路径，如合适的 libm。关闭近似并不自动补上另一套实现；产生库调用也不等于完成链接，LLVM 内建函数最终也可能由后端变成库调用。
