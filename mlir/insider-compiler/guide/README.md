# 逐章导读：读前准备与阅读路线

[校订正文总目录](../README.md) · [精华笔记](../notes/README.md) · [脚注与参考资料](../inside-compiler-refs.md)

导读回答三个读前问题：这一章为什么值得读，需要先知道什么，读正文时应抓住哪些联系。每章的详细结论、公式和接口归纳放在配套笔记中。材料由本书校订正文综合整理，不要求预先掌握全书才开始阅读。

技术基准沿用正文的 LLVM/MLIR **18.1.8**。第13章采用原书固定的 Triton 提交 `47fc046ff29c9ea2ee90e987c39628a540603c8f`；它有自己的 LLVM 依赖。较新版本的附录方言按正文注明的范围理解。文中的章节关系表示知识上的衔接，不是所有程序必须执行的编译流水线。

## 全书围绕什么问题展开

可以一直带着一个矩阵乘加偏置的例子阅读：高层看见的是算子和张量，中层需要决定分块、融合及存储复用，低层需要决定线程、地址与指令。每降低一层抽象，就要补充实现细节，并承担相应的正确性责任。

全书有四条相互连接的线索：

| 线索 | 核心问题 | 对应章节 |
| --- | --- | --- |
| 表达语义 | 怎样描述一个操作，以及它允许怎样被使用？ | 1～4 |
| 修改语义表示 | 谁调度变换，怎样匹配、替换和证明局部处理合法？ | 5～7、12 |
| 实现计算 | 怎样将算子组织成循环、缓冲区、向量与硬件程序？ | 8～11、13 |
| 证明循环变换 | 怎样用整数域、访问关系和约束求解支撑合法性判断？ | 14～15，并回读9 |

数学部分可以和工程部分交替阅读。读第9章 Affine 时先理解“可分析的整数循环”；需要弄清某次融合为什么不安全时，再深入第14～15章。

## 按学习目标选择路线

**第一次建立整体认识。** 先读1、2，浏览3、4的主要机制，再读5、6。此时回看第1章的线性层，应该已经能分别指出 IR 定义、Pass 调度和 RewritePattern 的职责。随后按书序阅读7～12，把13作为综合实例，最后用14、15解释循环分析背后的数学。

**准备开发方言或变换。** 以2 → 3 → 4 → 5 → 6为主线，接着用7中的现成优化观察接口如何参与通用算法。需要可编程编排或声明式匹配时读12；涉及缓冲化和目标表示时再接9～11。先完成一个小而闭合的定义—验证—改写过程，再扩展抽象层次。

**主要关心 GPU 与 Triton。** 具备2、4～6的基础后，重点读9中的 Linalg、Vector、Bufferization，再读11的线程、内存和目标方言，最后分段读13。第13章先看整体流水线，再理解布局映射，随后逐项理解优化为什么需要相应布局。性能论断始终结合目标、输入和编译配置。

**主要关心循环与数学。** 先读9.2中的 Affine 语法与限制，再读14的域、访问与依赖，最后读15的可行性、投影和整数求解。回到9.1的融合、分块时，分别问“访问到了什么”“顺序改变了什么”“怎样证明仍然合法”。

## 一章怎么读才容易留下结构

读前用本章导读补齐少量必要背景。读正文时选一个贯穿示例，标出操作、类型、形状、初值和执行顺序在各阶段的变化。读后用配套笔记检查自己能否解释一个机制及其前提，而不只是认出接口名称。

源码阅读也可以沿同一顺序进行：先找定义中的契约，再看算法如何查询接口和修改 IR，最后看测试如何区分合法输入与反例。[跨章知识串联](../notes/cross-chapter.md)给出了这一方法在全书中的对应关系。
