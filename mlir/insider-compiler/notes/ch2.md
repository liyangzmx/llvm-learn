# 第2章精华笔记：结构、语义与处理机制

[原章](../insider-compiler-ch2.md) · [配套读前导读](../guide/ch2.md) · [笔记目录](README.md)

本笔记按本地 LLVM18.1.8 校订正文整理，重点是后续章节反复使用的结构关系。

## 1. 四个构件回答不同问题（2.1.1）

| 构件 | 主要职责 | 易混边界 |
| --- | --- | --- |
| Operation | 表达某种语义与相关结构，可以是加法、函数或循环 | 不等同于一条机器指令 |
| Type | 描述 SSA 值的类型、形状等信息 | 有类型不代表所有维度都静态已知 |
| Attribute | 承载编译时数据和语义参数 | 不等同于一个运行时 SSA 输入 |
| Dialect | 组织相关操作、类型、属性及其行为 | 不是封闭的单一抽象层；方言可混用 |

一个矩阵乘可在高层表达为整体操作，在较低层表达为多重循环。两种表示都使用 Operation 等公共构件，但它们允许直接观察和变换的结构不同。普通 `linalg.matmul` 还会向 `outs` 初值累加，因此数学式 `C=A×B` 与任意初值的操作不能直接画等号。

## 2. 一段 IR 同时具有三种结构（2.1.2）

**递归包含**为 `Operation → Region → Block → Operation`。包含关系划定所有权与嵌套作用域；区域的执行语义由父操作定义。

**数据关系**由 SSA 定义—使用链构成。值可来自操作结果，也可来自块参数。改变结果类型或表示时，必须同时协调使用处，不能只替换产生值的操作名称。

**控制流**由相应操作及其后继关系表达。SSACFG 的分支可把值传给目标块参数，在合流位置发挥传统 Phi 的作用。三个结构叠加后，不能把 MLIR 简化为纯 AST，也不能只用平坦 CFG 解释嵌套区域。

| 比较项 | SSACFG 区域 | Graph 区域 |
| --- | --- | --- |
| 顺序意义 | 按控制流及块内顺序解释执行 | 不由操作文本次序规定执行先后 |
| 定义与使用 | 受相应 SSA 支配规则约束 | 可出现先使用、后定义的文本形式 |
| 块组织 | 可以包含多个块 | 本地实现中非空时只有一个块 |
| 仍需维护 | 类型、作用域、操作自身约束 | 同样有 SSA 值、类型和定义—使用关系 |

Graph 的“无 SSA 支配要求”不能改说成“没有 SSA”。嵌套区域还要求层次化支配分析；`DominanceInfo` 不只查询块之间的关系，也支持操作及值相关的查询。

## 3. 作用域与隔离是两道不同边界（2.1.2、2.3）

一般作用域规则禁止把区域内部值直接拿到区域外使用；需要传出数据时，应经过父操作所规定的结果等机制。`IsolatedFromAbove` 进一步限制反方向的隐式捕获：该操作拥有的区域不能直接引用边界外定义的 SSA 值。

隔离并不禁止按操作语义显式传入操作数、通过入口块参数接收数据，或使用符号引用。函数调用可以借助符号表找到目标，而不必建立跨隔离边界的全局 SSA Use-Def 链。

隔离也不单独保证线程安全。只有再遵守 Pass 不任意检查或修改同级 IR 等规则，才可能安全并行处理独立操作；共享上下文中仍有需要同步的状态。

## 4. 语法合法、IR 合法与变换正确不是同一件事（2.1.3、2.2.1）

文本、内存和字节码是 IR 的三种表示。解析文本会形成内存对象；自定义汇编格式改善可读性，并不改变操作必须满足的语义约束。通过 C++ API 构造的对象同样需要验证。

谓词表达布尔条件，约束包装谓词与诊断信息，特质附加公共性质或行为，接口让通用代码查询不同操作的能力。这些检查发生在编译器运行时处理 IR 的过程中，不是对目标程序运行行为的自动证明。一个变换完全可能产生能通过 verifier、却不保持原程序计算结果的 IR。

## 5. 重写与转换的关注点（2.2.2）

普通重写负责识别模式并创建、替换或删除 IR；调用者仍须保持数据关系与结构一致。方言转换框架在此基础上提供目标合法性、类型转换及操作数映射，处理更系统的表示变化。

| 模式 | 成功要求 | 不应据此推断 |
| --- | --- | --- |
| 部分转换 | 必须处理显式非法操作；允许原有、未显式非法的未知操作留下 | 可任意留下已经标为非法的操作 |
| 完全转换 | 转换范围中的操作均满足目标合法性 | 最后只能剩一种方言 |

张量矩阵乘降成缓冲区循环时，还要先处理缓冲化；`affine.for` 不是“输入类型换成memref的矩阵乘”。访存语义来自循环体内的操作。Pass 负责组织这些步骤的运行，具体顺序由编译器开发者安排。

## 6. 调试工具按问题选择（2.2.3～2.3）

| 想知道什么 | 合适机制 |
| --- | --- |
| 哪个 Pass 改坏了 IR | Pass 前后打印与验证 |
| 哪一次细粒度动作需要执行或跳过 | Action、Debug Counter |
| 怎样缩小仍能复现的问题 | Reduce 配合“问题仍存在”的判定测试 |
| 怎样保存并重放编译条件 | Crash reproducer 中的 IR、流水线和配置 |
| 新操作来自哪里 | Location 的传播与组合 |

Debug Counter 控制动作执行次数，不是打印次数；Reduce 搜索更小复现，不保证全局最小。TableGen 则把声明经记录交给生成器，既生成框架胶水代码，也可生成文档；它描述的是编译器基础设施，不是目标程序执行流程。
