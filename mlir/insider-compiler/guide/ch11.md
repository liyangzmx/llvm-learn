# 第 11 章导读：目标输出方言

[校订正文](../insider-compiler-ch11.md) · [精华笔记](../notes/ch11.md) · [导读目录](README.md)

本章讨论编译器怎样把高层计算交给目标机器。读完后，应能把“改变 MLIR 表示”“导出 LLVM IR”“生成目标代码”三个步骤分开，并能解释一个矩阵元素在 GPU 上由哪个线程、从哪一层内存读取。11.1 节以 llvm 方言说明通用输出边界；11.2 节借 SME 和 GPU 展示硬件特性如何进入 IR。

## 先补齐三个背景

**SSA 与 ABI。** SSA 值有类型和定义—使用关系；ABI 则规定函数边界上参数、结果及数据结构怎样表示。一个 `memref` 值包含地址、形状和步长信息，不能简单变成一个裸指针。回顾第 2 章的 SSA 与块参数、第 6 章的方言转换框架，以及第 10 章的 memref 后，再读 11.1.1 节会容易得多。

**并行坐标。** GPU 上一次程序启动形成 grid，grid 由多个 block 组成，block 内有多个 thread。以一维为例，元素坐标常由 `block_id * block_dim + thread_id` 得到；如果每个 block 处理一个 tile，还要区分 tile 起点与块内元素偏移。NVIDIA 的 warp 通常含 32 个线程，warp-group 与 thread-block cluster 又是不同层级。

**存储与同步。** 线程寄存器、工作组共享内存、设备全局内存有不同的可见范围和访问成本。“异步发出了拷贝”不等于“数据已能读取”；必须理解等待对象、同步参与者与缓冲区生存期。共享内存 bank 冲突与全局内存合并访问也属于两个问题。

## 按什么顺序阅读

先读 **11.1.1、11.1.4**，画出 ranked memref 描述符的五类字段，追踪一次 load 如何算地址。再读 **11.1.2～11.1.3**，辨认 MLIR 属性、块参数和常量在 LLVM IR 中的对应物。尤其留意：出现 llvm 操作不代表整个模块已经能够导出，残余 SCF 或未完成的类型转换仍可能阻断流程。

随后读 **11.2.3～11.2.4** 建立 GPU 执行模型，再比较 **11.2.5 的 nvgpu** 与 **11.2.6 的 nvvm**。前者表达 NVIDIA 专用计算和数据搬运结构，后者更接近 LLVM intrinsic 与 PTX 语义。**11.2.2 的 arm_sme** 可以单独阅读，重点是可伸缩向量长度、ZA tile 与物理资源分配，而非记住全部操作名。

## 带着问题进入正文

- 为什么 memref 的分配指针与访问指针要分开？函数参数展开与结构体值有什么区别？
- 一次 GPU 屏障究竟约束哪些线程？异步组等待能否替代所有层次的同步？
- 布局 swizzle 为什么必须同时改变读写下标？同一种 swizzle 为什么只对某些访问模式有效？
- 新硬件能力应放在通用 gpu 层、专用方言层，还是输出翻译接口中？

本章以 LLVM 18.1.8 为实现基准，较新硬件概念保留版本范围。读完可接第 13 章：Triton 的布局、共享内存与流水线会把这里的硬件知识串成完整编译过程；第 12 章则说明如何用 IR 编排这些变换。
