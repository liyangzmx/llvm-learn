# 第 14 章精华：用整数依赖关系判断循环变换

[校订正文](../insider-compiler-ch14.md) · [读前导读](../guide/ch14.md) · [笔记目录](README.md)

本章最重要的顺序是：准确表示迭代与访问，证明新执行顺序保持依赖，再估计收益。连续几何、整数可行性与 LLVM 18.1.8 的具体分析能力应分开。

## 1. 数学定义的适用范围（14.1～14.4）

| 对象 | 定义或性质 | 必须保留的前提 |
| --- | --- | --- |
| 仿射集 | $\alpha x+(1-\alpha)y$ 仍在集合中 | 任意实数 $\alpha$ |
| 凸集 | 两点之间的线段仍在集合中 | $0\le\alpha\le1$ |
| 锥 | $x$ 属于集合时，$\alpha x$ 也属于 | $\alpha\ge0$；锥不自动为凸集 |
| 多面体 | $P=\{x\in\mathbb R^n:Ax\le b,Cx=d\}$ | 有限个线性等式与非严格不等式 |
| 凸函数 | $f(\alpha x+(1-\alpha)y)\le\alpha f(x)+(1-\alpha)f(y)$ | 定义域凸，$\alpha\in[0,1]$ |

等式可以用两个反向不等式替代，不能直接删掉。凸集的交、仿射像仍凸；凸函数的非负加权和、与仿射自变量映射复合仍凸。任意线性组合、任意函数复合不具有同样结论。

在凸域上最小化凸函数，局部最小也是全局最小。严格凸性只保证最优解至多一个，不保证存在；一般凸函数甚至可以有整个最优面。最优值是下确界，有限下确界也未必被可行点取得。

循环的真实迭代点是 $P\cap\mathbb Z^n$，通常不是凸集。连续松弛可用于排除整数解或估计界，但有理数解不是可执行的半次迭代。因此不能用“保持凸性”代替编译变换的依赖证明。

## 2. 依赖关系的最小完整模型（14.5.1）

令源、目标动态迭代分别为 $s,t$，迭代域为 $D_S,D_T$，访问映射为 $F_S,F_T$。冲突候选至少要满足：

$$s\in D_S,\quad t\in D_T,\quad F_S(s)=F_T(t),$$

还要有可别名的存储对象、至少一次写，以及相应的源先于目标的执行顺序。普通读—读不阻止并行。不同 SSA 名称不普遍证明无别名；本地 Affine 接口直接跳过不同 memref 值，不能把这一接口边界当成通用别名定理。

两边迭代变量必须独立，即使源码文本同名。访问映射的逆是关系，未必是单值函数；组合访问关系时，对共同内存坐标做存在量化和消元，得到源、目标迭代对。

GCD 测试来自 $ai-cj=d-b$。当 $a,c$ 不同时为零，$\gcd(a,c)\nmid(d-b)$ 能排除整数相等访问；整除只能证明忽略边界与顺序的方程有解，不能证明真实依赖。

正步长 $h$ 需要同余约束 $i=lb+hq,q\in\mathbb Z$，再配合循环界。常量除法也引入整数局部变量，例如：

$$q=\lfloor e/4\rfloor\iff4q\le e\le4q+3.$$

这对负整数同样成立。只写区间会丢掉非单位步长的空隙。数学上可精确表达，不代表每个实现都完整支持；本地非常数下界的非单位步长可能作保守近似。

`MemRefAccess::getAccessRelation` 建模访问关系，不检查全部地址安全；动态形状仍有运行时边界。`IntegerRelation::isEmpty()` 在此分析中结合消元、GCD 等排除依赖，未能判空表示可能依赖，不等同于已经找到整数样本。

## 3. 某层并行取决于该层携带的依赖（14.5.2）

对第 $d$ 层，固定更外层坐标相同，再要求目标在这一层向后：

$$t_k=s_k\ (k<d),\qquad t_d\ge s_d+1.$$

若地址相等和迭代域约束与上述条件矛盾，就排除了这一层的相应跨迭代依赖。不能用内层坐标单独代表整组循环的字典序。

矩阵累加例子中，地址相等给出 $s_i=t_i,s_j=t_j$。分析外层 $i$ 或中层 $j$ 时与严格推进矛盾；内层 $k$ 仍可从 0 推进到 1 并访问同一输出元素。所以外两层可并行，内层累加保留顺序。还需检查初始化写、反向访问对、写—写、自身不同迭代及其他副作用。

`iter_args` 表示一般跨迭代状态，不只是归约。本地 `affine-parallelize` 需显式启用 `parallel-reductions=true` 才尝试支持的归约；出现加法不等于整条状态链可并行。浮点归约改变结合顺序时还要考虑数值语义。

## 4. 融合：合法切片与成本分别计算（14.5.3）

生产者—消费者融合利用写后读的数据复用；sibling fusion 也可以融合共享读取的循环。依赖不是简单的“有则融合、无则并行”二选一。

1. 建立基本块顶层操作或循环嵌套之间的内存及 SSA 依赖图。
2. 检查候选、插入位置及其他使用者，保证移动生产切片不破坏顺序。
3. 从消费地址求所需生产迭代，按融合深度合并切片；保守包围不等于任意集合的精确并集。
4. 比较新增动态计算与中间存储区域，再选择方案。
5. 插入切片、调整下标与图；仅在安全时删除原循环、缩小缓冲区。

原章区间 $10\ldots19$ 与 $15\ldots24$ 合并为 $10\ldots24$；单个消费者迭代可能只需要一个生产点，不能总把整个区间当成精确需求。

成本例子中，原生产成本 100、消费成本 110；融合后总成本 260，新增比例为 $50/210\approx23.81\%$，低于本地默认约 30% 的容忍阈值。缓冲区从 $100\times4=400$ 字节降到 $15\times4=60$ 字节，约缩小 6.67 倍；生产写却从 100 次增加到 150 次，累计写入从 400 增至 600 字节。这是工作集与重算的交换，不是访存速度提高 6.67 倍的证明。

## 5. 分块的距离条件与本地缺陷（14.5.4）

依赖距离定义为 $d=t-s$，是动态迭代坐标之差，不一般等于数组下标差。原循环中，$d=(1,-1)$ 仍按整体字典序指向后续迭代；负分量不说明原程序读取未来值。

对按块间、块内坐标递增的常见矩形分块，全部相关距离分量非负是一个合法性充分条件，零允许。它不是任意特定块大小合法的必要条件。更一般的检查应验证每条依赖在新调度下仍保持源先于目标。

本地 `affine-loop-tile` 主要针对完美嵌套循环，其 `checkTilingLegality` 使用 `lb < ub && ub < 0` 拒绝部分负方向，漏掉固定负分量 `lb == ub < 0`。已验证距离 $(1,-1)$ 的反例被错误接受为 $2\times2$ 分块，执行结果从 2 变成 1。**不能据该版本 Pass 接受变换就放弃数学合法性核对。** 这也不能证明 LLVM 20 必然有同样缺陷。

读源码时最后区分三种结论：数学上不存在依赖、实现保守地报告可能依赖、实现出现漏检。第 15 章进一步说明整数投影与求解为何影响前两者；输入、原生反例及实现边界见[本章校订记录](../issues/ch14.md)。
