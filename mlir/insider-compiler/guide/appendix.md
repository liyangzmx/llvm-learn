# 附录导读：补齐布局、运行时与特殊领域语义

[导读目录](README.md) · [附录正文](../insider-compiler-appendix.md) · [附录笔记](../notes/appendix.md)

附录把前面章节没有集中展开的七个方言放在一起。适合带着具体需求阅读：数据在目标上怎样排列，异步任务怎样等待，张量怎样分布到设备，低位宽数值怎样解释。它们没有一条固定的先后降级顺序。

## 先补齐四组背景

**类型大小和对齐是不同信息。** 一个指针可以占64位，同时具有不同的 ABI 对齐或推荐对齐要求；指针位宽也不等于其所指元素类型。回看第10章的 memref 和第11章的 LLVM 指针，再读 DLTI，会更容易理解为什么布局信息需要独立查询。

**编译期描述需要执行期配合。** 异步操作表达依赖与结果可用性，但具体调度需要运行时或后端实现；设备分片也要落实为局部计算和通信。不要只凭 IR 中出现了 `async` 或 `mesh` 就推断已经取得并行加速。

**数据的数学意义与存储表示需要分开。** 量化后的整数还需要 scale 与 zero point 才能解释数值；多项式在商环中相同，也不代表两个原多项式逐项相等。前者联系第8章的数值接入，后者提醒我们注意方言所采用的数学模型。

**毒值需要结合使用方式理解。** `poison` 的产生、传播及触发未定义行为的使用属于不同环节。具备这一认识后，再去阅读相关优化的副作用和可推测执行前提。

## 各节关注什么

| 正文位置 | 读前抓手 | 重点观察 |
| --- | --- | --- |
| 第1～2节：DLTI、Ptr | 第3章属性、第11章指针 | 布局属性描述哪些量，它们的单位是什么；本地与较新版本分别有哪些定义 |
| 第3节：UB | 值的产生与使用 | 为什么产生毒值不等于立即发生未定义行为 |
| 第4节：Polynomial | 模运算和等价类 | 原多项式相等与模某个多项式同余的区别 |
| 第5节：Async | 依赖、完成与等待 | IR 表达的异步语义怎样与运行时调度衔接 |
| 第6节：Mesh | 张量轴、设备网格、第9章索引映射 | 迭代空间怎样映射到张量下标，又怎样推导分片 |
| 第7节：Quant | 有限精度、比例和偏移 | 表达类型、量化类型、底层存储类型分别是什么 |

本地 LLVM18 中没有 Ptr、Polynomial 方言，Mesh 和 DLTI 的若干较新接口也不可照搬。读前先接受“同一个概念可以跨版本保留，接口名称和实现范围仍需按版本确认”，就不会把版本差异误当作不同数学语义。

## 带着三个问题读正文

1. 给模块附加一条布局属性后，哪个消费者会查询它并改变代码生成？
2. 一个张量从全量表示变为设备分片表示，哪些信息能从索引映射推导，哪些需要通信或运行时支持？
3. 把量化值转成底层整数类型，是否等于执行了一次数值量化？

读完后，把七个方言分别放回第3章的表示机制、第9～11章的实现过程和第12章的接口扩展中理解。附录的用途是补充这些主线所需的语义。
