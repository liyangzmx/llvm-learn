# 第1章精华笔记：降级的核心是信息与语义

[原章](../insider-compiler-ch1.md) · [配套读前导读](../guide/ch1.md) · [笔记目录](README.md)

依据当前校订正文及本地 LLVM18.1.8 整理。项目生态介绍保持原书的历史范围；下面聚焦可迁移的编译器设计认识。

## 1. 多层 IR 为何有价值（1.1～1.2）

领域信息一旦被拆成低层指令，后续优化往往要重新识别原来的结构。保留矩阵乘、循环、张量形状等信息，可以让优化直接依据这些结构工作；公共基础设施则减少不同前端各自实现解析、验证、变换和调试机制的重复。

LLVM IR 已经能表达向量与目标 intrinsic。MLIR 的动机不是填补“LLVM 完全不能描述向量”的空白，而是让不同抽象层次的信息在合适阶段继续可用。共享设施也不等于共享所有语义：领域方言仍需定义自己的操作含义、约束和转换规则。

| 设计问题 | 多层表示提供的机会 | 开发者仍须负责 |
| --- | --- | --- |
| 多语言接入 | 用领域方言承载语言结构，接入公共方言 | 正确导入源语言语义 |
| 公共优化 | 复用结构、接口、分析和重写设施 | 选择适用条件与执行顺序 |
| 硬件适配 | 在信息仍充分时转向硬件表示 | 并行映射、布局及指令选择 |
| 抽象跨度过大 | 增加中间步骤，分解转换任务 | 每一步的合法性和数值行为 |

方言与抽象层不是一一对应关系。同一模块可混用多个方言，同类方言之间也可能转换；图中的分层是组织思路，不是唯一合法路径。

## 2. 用线性层看清每层表达什么（1.3）

本例计算 $y=xA^{\mathsf T}+b$。$x$ 为 $1\times16$，参数 $A$ 为 $10\times16$，参数 $b$ 为长度10的向量。IR 可将权重预先排成 $16\times10$，并把偏置表示成 $1\times10$；这些形状调整必须保持相同元素及对应关系。

| 表示 | 本例直接可见的信息 | 尚不能据此断言 |
| --- | --- | --- |
| PyTorch 线性层 | 参数、输入输出与层的计算意图 | 参数已经训练，或前端编译已执行 |
| TOSA | 矩阵乘、reshape、逐元素加偏置 | 必然采用标量循环实现 |
| Linalg | 输入输出索引映射、parallel/reduction 维度、标量计算体 | 已选定最优调度和存储布局 |
| Affine + MemRef | 循环边界、访问下标、显式读写 | 已经是汇编，或天然适合全部目标 |
| LLVM 方言 | 分支、指针和低层运算的 MLIR 表示 | 与外部 LLVM IR 的语法相同 |

本地 TOSA 转换使用零初始化的 `linalg.batch_matmul` 等操作。正文的二维 `linalg.generic` 是便于说明的等阶段表达，不是该 Pass 的逐字输出。

## 3. 偏置后加是需要维护的计算阶段（1.3.3～1.3.4）

当前清单1-4～7统一采用：

```text
acc = 0
按归约顺序执行：acc = f32(acc + f32(x[k] * W[k,j]))
完成归约后：y[j] = f32(acc + b[j])
```

不能无条件把初值改为 `b[j]`，然后省去末尾加法。浮点加法受舍入影响，不满足一般结合律。例如采用 IEEE binary32、舍入到最近偶数，指定顺序的乘积为 $(2^{24},-2^{24},0,\ldots)$，偏置为1：从0归约再加1得到1；从1开始累加，第一步的1被舍入丢失，最终得到0。

因此，实数公式相同只是推理起点，不能单独证明浮点变换合法。保持偏置的加入阶段，也不意味着所有前端、归约调度、FMA策略或目标后端已经获得逐位等价证明。当前[独立验证](../issues/evidence/reading-edition/ch1/README.md)覆盖新版 Affine 标量实例；旧目录中的 bias-first 测试是历史记录。

## 4. 缓冲化改变的是责任分配（1.3.4）

Tensor 以值语义表达计算结果；memref 表示带形状、布局和内存空间信息的缓冲区引用。从返回张量改成输出参数，需要安排存储分配、初值设置、别名关系、函数接口和生存期。正文的手工 Affine 示例要求输入输出缓冲区互不重叠。

只把 `tensor` 字样换成 `memref`，或只运行循环降级 Pass，不能自动解决这些问题。后续章节中的缓冲化分析，正是在决定哪些值可共享存储、哪些必须复制。

## 5. 阅读 IR 的几个稳定区分（1.3.2、1.3.5～1.3.6）

- `func.func` 是操作名，`forward` 是函数符号；函数形参是入口块参数，不是这个函数定义操作的 SSA operands。
- `%0` 指 SSA 值。常量操作产生 SSA 结果；`DenseElementsAttr` 保存编译时常量内容，不能由它直接推断运行时张量布局。
- Affine 到 LLVM 方言仍在 MLIR 内部；导出 LLVM IR 需要翻译接口，不能删除操作名中的 `llvm.` 前缀代替翻译。
- 清单中的截断权重、未给出的前端环境和向量化上下文，是示例范围，不是可直接运行的完整链路。

## 6. 从架构收益回到工程判断（1.4）

MLIR 提供的是保留信息、共享设施和逐步转换的能力。是否更快，要看优化选择与实际测量；是否正确，要看语义约束、验证和执行证据。复杂数学、生成代码、版本接口以及上下文管理也形成学习成本。评价一条编译路线时，应同时检查它保留了哪些信息、承担了哪些转换义务，以及哪些结论已有验证。
