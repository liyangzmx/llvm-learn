以下原书较大差异保留为原文摘录，以便与 raw 定位对照：

> 当发生可恢复的错误时，MLIR 框架会尽可能地恢复错误并执行恢复动作。
>
> 同样，当值句柄被使用时，与负载操作相关联的操作句柄、负载操作的内嵌操作句柄、操作的返回值以及这些无效操作中的参数句柄也都会变为无效。
>
> 而负载操作自身主要涉及两种副作用：读和写。之所以不涉及删除，是因为负载操作不会自行删除，删除操作由变换操作触发执行。

这些内容分别混淆了错误抑制与恢复、句柄读取与消费、以及编译器 IR 的变化与负载程序运行时效果，故不能只改几个术语后保留原论断。

### 核心操作和接口的具体更正

PDF 37 的全部原操作名称均保留，按 [TransformOps.td](/opt/llvm-project/mlir/include/mlir/Dialect/Transform/IR/TransformOps.td:443) 校订：

- `match.operation_empty` 检查空关联列表，不是空操作；`match.param.cmpi` 比较整数参数属性列表，成功/失败而非返回操作筛选结果。
- `get_defining_op` 的输入是值；`get_operand`、`get_result` 的输出是值句柄；`get_type` 取得值的类型，以参数属性表达。
- `select` 筛选已有操作关联；`apply_patterns.canonicalization`、`apply_conversion_patterns.dialect_to_llvm` 是模式描述，需在外围相应应用操作中使用。
- `cast` 改句柄的类型表达，不改变负载值类型；`replicate` 重复关联，不克隆负载；`num_associations` 也能统计值及参数属性；`param.constant` 不生成负载常量操作。
- `alternatives` 可以所有分支都失败；`annotate` 会添加负载属性。

PDF 38–40 的五个核心接口与十四个辅助接口/特质/约束均保留。依据为 [TransformInterfaces.td](/opt/llvm-project/mlir/include/mlir/Dialect/Transform/IR/TransformInterfaces.td:122)、[MatchInterfaces.td](/opt/llvm-project/mlir/include/mlir/Dialect/Transform/IR/MatchInterfaces.td:23)、[TransformInterfaces.h](/opt/llvm-project/mlir/include/mlir/Dialect/Transform/IR/TransformInterfaces.h:1260)。主要更正：

- 操作句柄、值句柄、参数分别验证 `Operation *`、`Value`、`Attribute`，可用于变换输入/结果，不是原书描述的三种重叠的“操作数/返回值”接口。
- `SingleValueMatcher` 使用 `matchValue()`，关联的是一个值；`TransformEachOpTrait` 逐个负载操作调用 `applyToOne()` 并汇总结果。
- `ParamProducerTransformOpTrait` 产生参数；`ReportTrackingListenerFailuresOpTrait` 请求报告重写跟踪器失败。
- `FindPayloadReplacementOpInterface` 有实际的 `getNextOperands()` 契约，用于沿指定操作数继续查找替代负载，绝非与前一特质相同的“错误传播占位符”。
- `PatternDescriptorOpInterface` 与 `ConversionPatternDescriptorOpInterface` 分别面向贪婪重写和方言转换；`Transform_AnyHandleType` 等是约束，不是新具体类型。

## PDL / PDLL 校订

### 清单 12-7：类型语法与重写约束

原书关键代码为：

```text
%resultType = pdl.type
%inputOperand = pdl.operand
%root = pdl.operation "foo.op"(%inputOperand) -> %resultType
pdl.rewrite %root {
  pdl.replace %root with (%inputOperand)
}
```

本地语法要求相关 PDL 操作数的类型标注，见 [PDLOps.td](/opt/llvm-project/mlir/include/mlir/Dialect/PDL/IR/PDLOps.td:188)。正文补全标注，并让输入也受 `%resultType` 约束，否则会匹配输入 i32、输出 f32 的操作，再用 i32 值替换 f32 结果。实测同型情形被消除，异型情形保留 `foo.op`。仍需业务语义保证 `foo.op` 可消除；任意操作名称和形状匹配不构成语义证明。

原书列出的十五个 PDL 操作完整保留，修正 `attribute` 不只常量、`range` 构造范围而不自动批量执行、`operation` 在重写区可创建操作等描述。

### pdl_interp 的层次与性能

原书：

> 它的主要作用是优化由 pdl 方言生成的代码。pdl_interp 方言采用字节码存储模式……与用 C++ 编写的模式相比……执行性能上可以提升 15 倍，编译后的二进制代码量可减少 90%。

正文保留 15 倍与 90% 数据作为原书所报告的特定性能结果，并明确未复现，不能泛化。pdl_interp 本身是较低层模式 IR；私有字节码由冻结模式集时的后续步骤产生，单独 `--convert-pdl-to-pdl-interp` 输出仍是 IR 文本。依据 [FrozenRewritePatternSet.cpp](/opt/llvm-project/mlir/lib/Rewrite/FrozenRewritePatternSet.cpp:23)、[字节码生成](/opt/llvm-project/mlir/lib/Rewrite/FrozenRewritePatternSet.cpp:128)。

共享判定结构与紧凑字节码可降低开销，但“压缩”不是额外通用压缩算法。最佳分支算法用于多根模式根顺序，见 [RootOrdering.h](/opt/llvm-project/mlir/lib/Conversion/PDLToPDLInterp/RootOrdering.h:82)，不能据此断言整个匹配树普遍最优。

`FrozenRewritePatternSet` 中启用/禁用集合用于原生模式过滤；启用不代表必须运行。PDL 模式字节码的生成位于独立分支中。正文注意框保留，并纠正原书“必须运行”的解释。

## IRDL 的语法、约束与算法差异

### 清单 12-11

原书代码完整保留如下，花括号和明显 OCR 字符已恢复：

```mlir
irdl.dialect @cmath {
  irdl.type @complex {
    %0 = irdl.is f32
    %1 = irdl.is f64
    %2 = irdl.any_of(%0, %1)
    irdl.parameters(elem: %2)
  }
  irdl.operation @mul {
    %0 = irdl.is f32
    %1 = irdl.is f64
    %2 = irdl.any_of(%0, %1)
    %3 = irdl.parametric @cmath::@complex<%2>
    irdl.operands(args: %3, elem: %3)
    irdl.results(re: %3)
  }
}
```

本地两项独立差异均有实测：

- 命名形式在本地解析时失败，正文改为 `irdl.parameters(%2)`、`irdl.operands(%3, %3)`、`irdl.results(%3)`。记录为版本差异。
- 仅删除名称后，文本能解析，但通过 `--irdl-file` 动态加载时，`@cmath::@complex` 无法在此作用域解析；改为 `@complex` 后加载及使用通过。不能把“IRDLOps 能解析”当作“定义已成功动态注册”。

共享 `%3` 要求两个操作数与结果是同一具体类型，不是分别属于 f32/f64 联合范围即可。合法 f32 输入通过；将第二操作数改为 complex<f64> 后，实际诊断 `expected '!cmath.complex<f32>' but got '!cmath.complex<f64>'`。

IRDL 自身是实现好的元方言，其描述的方言可动态注册；SSA 约束与其运行时 Attribute/TypeAttr 表示也作了区分。17 个关键操作完整保留。`c_pred` 不能由本地运行时加载器注册，参见 [IRDLOps.td](/opt/llvm-project/mlir/include/mlir/Dialect/IRDL/IR/IRDLOps.td:635)；`region` 产生区域约束，`regions` 将约束附到定义上，并非直接创建业务 IR 的区域。

### 清单 12-12 与回溯

原书写道：

> 这主要是因为使用 irdl 定义的方言需要动态注册到 MLIRContext 中，部分信息只有在注册之后才能使用，这导致其验证过程必须进行信息回溯，从而增加了 IR 验证的成本。

原书随后用 `irdl.constraint_var(T: !Any)` 和 `AnyOf<T, vector<T>>` 说明先绑定 T 为 vector<f32> 失败，再回溯绑定为 f32 成功。正文保留完整伪代码及两种选择的推演，但不能声称这就是本地算法。

本地 [IRDLLoading.cpp](/opt/llvm-project/mlir/lib/Dialect/IRDL/IRDLLoading.cpp:530) 明确采用贪婪匹配，注册时限制 `any_of` 分支；不支持本例所需要的通用回溯。证据 `overlap.mlir` 是只抽取“通配约束与向量种类重叠”这一核心问题的最小示例，**不是清单 12-12 的完整等价翻译**。它普通解析通过，动态加载拒绝并输出 `any_of constraints are not in the correct form`。

研究中的 `irdlssa` / `irdlinterp` 保留为原书引用的研究方案，不称作本地已实现的方言。动态注册本身不必然要求验证回溯；复杂性源于约束表达及求解策略。
