# 第3章读前导读：从方言声明走到内存对象

[原章](../insider-compiler-ch3.md) · [配套精华笔记](../notes/ch3.md) · [导读目录](README.md)

## 本章要解决的问题

前两章告诉我们 IR 有哪些构件，本章追问这些构件在编译器中如何存在：一个 `i32` 如何取得，一次 `arith.addi` 如何创建，方言注册后又由谁保管数据。全章代码较长，主线不是背生成代码，而是始终区分**定义、注册元数据、具体存储、访问句柄**。

## 需要准备的 C++ 概念

轻量句柄通常只持有指向其他对象的引用；复制句柄不等于复制底层数据。模板别名可以封装复杂基类，CRTP 则把具体类型作为模板参数交给公共基类，实现静态行为复用。Placement new 在已经分配的地址上构造对象，本身不说明这段空间如何取得。读到这些机制时，把“谁分配、谁拥有、谁只是访问”写在旁边，比展开所有模板更有帮助。

还要分清两段时间：TableGen 在构建编译器时生成代码；运行编译器后，context、方言和 IR 对象才参与具体编译任务。TD 记录中的一个字段，不必对应每个操作对象里的一个独立成员。

## 按原章安排阅读

**3.1 类型**：跟踪 `IntegerType`，看位宽和符号语义怎样进入存储键。先理解 `Type` 与 `TypeStorage` 的分工，再顺着 `get()` 看到唯一化查找。TD、展开记录、生成声明三份清单要对照读，不必把每个匿名记录编号当成知识点。

**3.2 属性**：借已有的类型模型快速理解属性；随后单独停在3.2.3，辨别“固有/可丢弃”这一语义分类和 properties 这一存储机制，避免把两种分类混为一谈。

**3.3 操作**：以 `AddIOp` 为线索，分别回答声明提供什么、`build()` 填什么、`create()` 分配什么。内存图先看前置结果区、本体、尾部存储三个区域，再看局部字段。字节偏移只属于本机 ABI，不是必须背诵的通用常量。

**3.3.2 的类型转换**：留意这里主要讨论从 `Operation*` 取得具体操作句柄，不是第6章改变 IR 值类型的 TypeConverter。两个“转换”的对象和结果不同。

**3.4～3.5 方言与上下文**：回收全章线索，追踪“注册可加载的方言→加载并初始化→注册构件→请求具体值或创建操作”。阅读扩展时，关注它何时应用、给谁附加能力；不要预设任何方言都能任意动态增加操作。

## 带着这些问题读

1. 同一 context 中两次取得相同整数类型，与两次创建相同加法操作，身份为什么不同？
2. `AddIOp` 不继承 `Operation`，为什么仍能使用 `dyn_cast`？
3. `sizeof(Operation)` 固定，为什么不同操作仍需要不同大小的分配块？
4. `DialectRegistry::insert` 之后，方言对象是否已经构造？

本章按本地 LLVM18.1.8 校订实现，尤其留意 properties 与六个内联结果的实际代码依据。第4章将利用这里的元数据和句柄解释接口分派；第5章开始管理对操作实例的处理过程。首次阅读抓住所有权与生命周期，之后再把文法和字段表作为查阅材料。
