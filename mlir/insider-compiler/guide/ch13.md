# 第 13 章导读：Triton 编译器

[校订正文](../insider-compiler-ch13.md) · [精华笔记](../notes/ch13.md) · [导读目录](README.md)

这是全书最长、代码最密集的一章。它将前面分散的方言、转换和硬件知识接成一条实际路径：Python 中的块状张量程序，逐步获得线程布局、通信方式和执行时序，最终成为 GPU 目标代码。首次阅读不必逐行跟完每份中间快照；先为每一阶段写下“新增了什么决策”，再挑一条 load—dot 数据流贯穿长清单。

## 先补齐三个模型

**程序块与线程。** 一个 Triton program 通常处理一个 tile；`program_id` 选择 tile，`arange` 表示 tile 内逻辑元素。源码中的张量运算并不直接等于单个线程的标量指令。线程分工要到布局阶段才逐渐具体化，尾部元素仍需合法的地址及 mask。

**布局是所有权映射。** 一个逻辑元素由哪个线程、哪个寄存器持有，属于分布式布局问题；某个元素在共享内存中的地址则属于 shared 布局问题。改变布局有时只改寄存器解释，有时需要 warp shuffle，有时必须经过共享内存与屏障。先掌握第 11 章的 warp、共享内存和 bank，再读 **13.3.4**。

**流水线不是简单移行。** 加载提前会延长值的生存期，需要额外缓冲、循环携带参数与等待关系。启动、稳态和排空都必须覆盖正确迭代，短循环和最后几轮尤其容易出错。第 10 章的 SCF 结构是阅读这些清单的基础。

## 建议分三轮读

第一轮读 **13.1～13.2、13.3.1～13.3.2**，记住 Python → TTIR → TTGIR → LLVM 等 MLIR 方言 → LLVM IR → PTX → CUBIN 的边界。这里采用固定 Triton 提交 `47fc046ff29c9ea2ee90e987c39628a540603c8f`，与本地 LLVM 18.1.8 是两套版本基准；新版本名称不能随意混入旧流水线。

第二轮精读 **13.3.3～13.3.4**。观察指针、广播和 dot 在布局决定前能做哪些变换，再手算一个 blocked 布局的线程分配和一个 shared 布局的 swizzle。这比背参数名更能解释后续优化。

第三轮读 **13.3.5** 的 12 项优化。按“访存与线程分工”“布局转换”“矩阵指令选择”“预取与调度”分组，但以 **13.3.1** 的实际 Pass 顺序理解它们如何交织。Prefetch 小节先讲不代表它在固定流水线中先于 Pipeline。最后读 **13.3.6**，看共享内存字节数如何从分析进入启动元数据。

## 带着四个问题核对长清单

- 一个 `convert_layout` 前后，逻辑值是否相同？代价发生在寄存器、warp 内还是跨 warp？
- Prefetch 提前的是共享内存到寄存器，Pipeline 重点覆盖的是哪段数据搬运？
- 三个调度阶段为什么可能只用两个缓冲槽？最后一轮怎样避免多发无效拷贝？
- 减少寄存器压力是否可能增加加载次数？共享内存占用下降是否必然更快？

正文已经区分结构测试、未完成的内部快照与完整输出。遇到无结果使用、重复地址或额外预取时，先看其用途与前提。第 14～15 章能进一步解释依赖合法性；不要因为某份调度表看起来合理，就把它当成一般程序的正确性证明。
