# 第4章读前导读：怎样让通用算法理解自定义操作

[原章](../insider-compiler-ch4.md) · [配套精华笔记](../notes/ch4.md) · [导读目录](README.md)

## 本章要解决的问题

第3章解决了“对象怎样定义与创建”，本章进一步问：什么样的对象才合法？多个操作怎样共享性质？通用优化又如何使用各方言不同的实现？谓词、特质、接口分别参与这些问题，实际使用时又会组合出现。阅读重点是分清它们提供什么、框架如何使用，而不是把它们分成互不相干的三套机制。

## 先准备几个概念

谓词是返回真假的条件；约束在条件之外增加说明等信息。一个字段要求F16，另一个字段要求F32，与“某字段允许F16或F32”是不同约束。先理解这个差别，再读生成的 verifier。

特质通常借助模板继承附加性质或公共实现；接口则让调用方按共同能力访问不同实体。静态模板与运行时分派可以协作，不必二选一。前章的操作句柄也值得复习：取得接口通常是在已有操作和模型上建立访问包装，并不是新造一份操作。

## 按原章抓住关键例子

**4.1 谓词**：沿清单4-2～4-5追踪一条类型条件怎样变成检查代码。关注 `$_self` 最终指什么，以及检查何时运行；普通 `create()` 并不自动证明操作合法。常见谓词列表适合查阅，不必首遍全部记忆。

**4.2.1～4.2.2 特质**：给每个例子标注用途：影响生成、声明性质，还是提供验证与公共实现。读参数化特质时，看清 TD 声明如何对应 C++ 模板；不要把特质声明当成业务实现已经生成。

**4.2.3 常见特质**：优先理解后文优化会依赖的契约，如隔离边界、可推测性、内存效果和终结操作。试着区分“没有内存写入”与“可以多执行一次”，这会直接影响操作能否提升。

**4.3.1 方言接口**：以内联接口为入口，观察通用框架怎样询问不同方言的合法性和处理方式。先把它当成完整例子读懂，再进入更复杂的操作接口。

**4.3.2 操作接口**：围绕 `getComputationCost()` 追一条调用链即可。为 `Concept`、`Model`、`FallbackModel`、`ExternalModel` 标出各自作用，不必一次展开全部生成代码。清单4-19要结合“是否有默认实现”来比较，不能只看三种TD写法表面不同。

## 带着这些问题读

1. 验证器检查了输入类型，是否就能证明优化前后计算结果相同？
2. 为什么一个操作没有内存效果，仍可能不能安全推测执行？
3. 不修改已有操作类，怎样为它补充一种通用算法需要的能力？
4. 接口方法体、默认实现与操作自身的方法，分别在哪条调用路径上生效？

第5、6章会使用本章的接口与契约来组织调度和重写；后续控制流、缓冲化等通用算法也依赖这些能力描述。这里以本地 LLVM18.1.8 的生成与注册行为为准，尤其不要把 ExternalModel 理解成自动覆盖已有实现的补丁机制。
